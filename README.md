# Vera AI

Vera AI is an auditing-focused AI platform built with Next.js, Supabase, Anthropic, and Stripe.

This repository currently contains:

- Deliverable 1: Agent AI Workspace (auth, chat, agent builder, settings, billing, admin)
- Deliverable 2: Marketing website scaffolding (route group and baseline structure)

The goal of this README is to let any developer clone this project, run it, and start building features or agents confidently.

## 1. Tech Stack

- Framework: Next.js 16 (App Router, Turbopack in dev)
- Language: TypeScript (strict mode)
- UI: Tailwind CSS v4 + shadcn/ui + Radix + Motion
- Auth/DB/Storage: Supabase (`@supabase/ssr`)
- AI Runtime: AI SDK (`ai`, `@ai-sdk/react`)
- AI Provider: Anthropic (`@ai-sdk/anthropic`, `@anthropic-ai/sdk`)
- Payments: Stripe (subscriptions + portal + webhook)
- Forms/Validation: React Hook Form + Zod

## 2. Quick Start

### Prerequisites

- Node.js 20+
- pnpm 9+
- Supabase project (URL + publishable key + service role key)
- Anthropic API key
- Stripe keys (for billing features)

### Install

```bash
pnpm install
```

### Configure environment

Create `.env.local` in the project root:

```bash
# Supabase
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SERVICE_ROLE_KEY=

# Anthropic
ANTHROPIC_API_KEY=

# Stripe
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=
STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=

# Optional dev bypass (never enable in production)
VERA_DEV_BYPASS_AUTH=false
```

Notes:

- This codebase uses `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (not `NEXT_PUBLIC_SUPABASE_ANON_KEY`).
- `SUPABASE_SECRET_KEY` is also supported as a fallback for service access, but use `SUPABASE_SERVICE_ROLE_KEY` as the primary variable.

### Run

```bash
pnpm dev
```

Open http://localhost:3000.

### Production build check

```bash
pnpm build
```

## 4. Project Structure

Top-level directories you will use most:

- `app/` - routes, layouts, API handlers
- `actions/` - server actions
- `lib/` - domain utilities, Supabase clients, DB helpers, models
- `components/` - shared UI primitives and feature-level reusable components
- `hooks/` - client hooks

## 6. Data and Auth Architecture

Supabase client usage:

- Server components/actions/routes: `lib/supabase/server.ts`
- Browser client: `lib/supabase/client.ts`
- Service-role operations: `lib/supabase/service.ts`

Design principles used in this repo:

- All sensitive operations run server-side.
- Service-role keys are never exposed to client components.
- Role-sensitive operations are validated on the server.
- API routes and server actions enforce auth before work.

## 7. Chat and Agent Architecture

### Chat flow (high level)

1. User submits prompt from composer.
2. Session route `/api/chat/[id]` streams responses using AI SDK + Anthropic.
3. Messages are persisted in Supabase.
4. Session titles are generated by `/api/chat/title`.
5. Exports supported via `/api/chat/[id]/export` (PDF/Markdown/Text).

Important implementation detail:

- Message parts are sanitized to JSON-safe persisted shapes before DB writes (text/file subset).

### Agent builder flow

- Builder UI: `/dashboard/agents/new`
- Builder chat API: `/api/agent-builder/chat`
- Agent CRUD actions: `actions/agent-actions.ts`
- Agent DB helpers: `lib/db/agents.ts`

## 8. Attachment Setup (Required for PDF/DOCX chat uploads)

Run this SQL in your Supabase SQL editor:

- `db/chat-attachments-setup.sql`

What it does:

- Adds JSONB columns for persisted message parts.
- Creates/updates `chat-attachments` storage bucket.
- Applies upload/delete storage policies for authenticated users.

If this step is skipped, chat attachment upload endpoints will fail.

## 9. Stripe Billing Setup

Billing endpoints:

- `/api/stripe/create-checkout`
- `/api/stripe/create-portal`
- `/api/stripe/webhook`

You must:

1. Set Stripe environment variables.
2. Expose local webhook endpoint (for local testing).
3. Configure webhook signing secret as `STRIPE_WEBHOOK_SECRET`.

## 10. Model Configuration

Model handling is centralized in `lib/models.ts`.

- Fallback models are defined (Haiku/Sonnet/Opus).
- Reasoning support is determined per model.
- Model aliases are normalized by `resolveModelId`.

## 11. Conventions for Contributors

- Use kebab-case for file and folder names.
- Prefer server components by default; use client components only when needed.
- Avoid `any`; use explicit types or `unknown` with narrowing.
- Keep Supabase queries in `lib/db/*` when practical.
- Use `cn()` from `lib/utils.ts` for class composition.
- Validate external/user input with Zod in APIs and actions.

## 12. How to Start Building a New Agent Feature

Typical workflow:

1. Add or update DB helpers in `lib/db/agents.ts`.
2. Add server action in `actions/agent-actions.ts`.
3. Build UI inside route-local `components/` under the relevant route.
4. If needed, expose secure API behavior from `app/api/...`.
5. Run:

```bash
pnpm typecheck && pnpm lint && pnpm build
```

## 13. Troubleshooting

### Build passes locally but runtime fails on Supabase operations

- Verify `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- Verify `SUPABASE_SERVICE_ROLE_KEY` for service operations.

### Attachment uploads fail

- Confirm `db/chat-attachments-setup.sql` has been executed.
- Confirm bucket and policies exist in Supabase Storage.

### Billing endpoints error

- Check `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`.
- Confirm webhook event delivery and signature validation.

### Auth callback issues

- Verify Supabase Auth redirect URLs include your local and deployed callback URLs.
